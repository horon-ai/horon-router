# 같은 모델을 다른 제공자로 자동 전환하기

`quota-failover`는 남은 사용량이 소진된 계정을 제외하고 **같은 공개 모델 이름을 등록한 다른 계정이나 제공자**를 선택합니다. 서로 다른 모델을 자동으로 비슷한 모델이라고 추측하지 않습니다.

```yaml
routing:
  strategy: quota-failover
  session-affinity: true
```

기존 설정에 이 두 값을 추가합니다. 실행 중인 설정 파일을 바꾸면 기존 설정 갱신 경로로 반영됩니다. 별도 구독이나 인증 정보를 자동으로 추가하지는 않습니다.

## 같은 모델을 묶는 방법

제공자마다 실제 모델 이름이 다르면 기존 별칭 설정으로 같은 공개 이름을 등록합니다. 아래는 Command Code의 `gpt-5.6-luna`와 Devin의 `devin/gpt-5-6-luna`를 같은 이름으로 묶고, OpenCode Go도 같은 이름으로 노출하는 예입니다.

```yaml
routing:
  strategy: quota-failover
  session-affinity: true

oauth:
  model-alias:
    devin:
      - name: devin/gpt-5-6-luna
        alias: gpt-5.6-luna
        fork: true

api-keys:
  openai-compatibility:
    - name: opencode-go
      base-url: https://opencode.ai/zen/go/v1
      keys:
        - api-key: YOUR_OPENCODE_GO_KEY
      models:
        - name: UPSTREAM_MODEL_ID
          alias: gpt-5.6-luna
```

`UPSTREAM_MODEL_ID`에는 OpenCode Go에서 실제로 제공하는 동일 모델의 이름을 넣습니다. 이 예시는 OpenCode Go가 그 모델을 제공한다고 선언하는 목록이 아닙니다. 모델 목록과 전송 형식이 맞아야 후보가 정상 실행됩니다. 다른 모델을 같은 별칭으로 등록하면 그 차이는 사용자가 허용한 대체가 됩니다.

Command Code와 Devin은 기존 로그인으로 등록한 인증 파일을 사용합니다. Command Code의 내장 모델 이름과 동일한 이름을 OpenAI 호환 그룹에 등록하면 별도 Command Code 별칭 없이 같은 후보 목록에 들어갑니다. `force-model-prefix`로 제공자별 모델 이름을 강제 분리하거나 요청에서 제공자를 고정하면 그 범위 밖의 제공자로 전환하지 않습니다.

## 사용량 소진 판단

| 제공자 | 선택에 사용하는 관측 |
|---|---|
| Command Code | 5시간·주간 창의 `used/cap`, 월간·구매·무료 크레딧 풀 |
| Devin | 사용자 상태 조회의 일간·주간 잔여 비율과 초기화 시각 |
| OpenCode Go | `/usage`의 rolling·weekly·monthly 사용률 |
| Claude·Codex | 기존 실행기가 응답 헤더에서 관측한 사용량 창 |

OpenCode Go는 기존 OpenAI 호환 실행기를 사용합니다. 기본 목적지 주소나 그룹 이름 `opencode-go`로 인식하며, 다른 주소를 설정하면 그 주소의 `/usage`를 조회합니다. 해당 목적지에는 그 그룹의 키와 프록시만 사용합니다.

하나라도 아직 초기화되지 않은 제한 창이 소진됐으면 제외합니다. Command Code는 모든 크레딧 풀이 확인됐고 모두 0 이하인 경우에도 제외합니다. 구매 크레딧이 남았더라도 별도의 제한 창이 소진됐다면 사용할 수 없습니다.

Devin의 응답 형식은 없는 숫자를 0으로 표현할 수 있으므로 초기화 시각이 없는 0은 소진 증거로 사용하지 않습니다. 조회 실패, 빠진 항목, 해석할 수 없는 값은 모두 불명확 상태입니다. 불명확한 계정은 실행 후보에 남습니다.

사용량 조회는 요청이 도착했을 때 필요한 후보에만 수행합니다. 성공·실패 결과를 최대 60초간 재사용하고 계정별 동시 조회를 하나로 합칩니다. 한 조회 묶음은 최대 3초이며 동시에 최대 4개 계정을 확인합니다. 처음 호출하거나 캐시가 만료된 호출에는 이 확인 시간이 추가될 수 있습니다. 토큰·주소·계정 객체가 바뀌거나 설정이 갱신되면 이전 조회를 재사용하지 않습니다.

## 전환 동작

1. 모델을 제공하지 않거나 사용량이 소진된 계정을 제외합니다.
2. 기존 대화에 묶인 계정이 남아 있으면 유지합니다.
3. 그렇지 않으면 기존 우선순위와 제공자 후보 순서를 적용합니다. 같은 그룹 안에서는 첫 계정을 선택합니다.
4. 실패 시 기존 계정 재시도와 대기 상태 처리를 사용합니다.

잔여량이 많은 계정으로 요청마다 이동하는 방식은 아닙니다. 사용할 수 있는 계정에 대화를 유지해서 캐시 재사용 기회를 보존합니다. 실제 제공자 캐시는 다른 제공자로 복사되지 않습니다.

Command Code가 잔액 부족을 `400 BAD_REQUEST`와 `insufficient credits` 메시지로 반환하면 이 전략에서만 계정 전체 소진 오류(429)로 분류하고 다음 후보를 시도합니다. 일반적인 잘못된 요청 400은 전환하지 않습니다.

응답 출력이 시작된 뒤 다른 제공자의 답을 이어 붙이지 않습니다. 기존 스트림 재시도 경계와 서버측 응답 ID가 있는 연결의 계정 고정 계약은 그대로 적용됩니다. 모든 후보가 소진됐으면 기존 인증 정보 사용 불가 오류로 끝납니다.

## 검증 범위

회귀 테스트는 실제 HTTP 라우터와 로컬 모의 제공자를 사용합니다. 소진된 우선 계정 제외, 사용량 불명확 계정 유지, 기존 방식의 조회 미실행, 건강한 조회 이후 잔액 부족 오류 전환, OpenCode Go와 Devin 사용량 조회를 검증합니다. 실제 구독 계정과 캐시 적중률은 이 테스트에서 사용하거나 측정하지 않습니다.
